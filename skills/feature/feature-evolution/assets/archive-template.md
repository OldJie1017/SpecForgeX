# CR-{{编号}} — 归并清单（{{功能名}}）

> 归档时照单执行：逐项就地修改正典文档，并在被修改文档末尾追加变更日志。
> 不受影响的文档/章节不出现在本清单。

## 正典归并项

| 文档 | 位置 | 操作 | 内容 |
|------|------|------|------|
| `specs/features/{{功能名}}/需求.md` | {{如：AC 列表-Edge Cases 分组}} | 新增 | {{AC-0xx 条目全文（Given-When-Then）}} |
| `specs/features/{{功能名}}/需求.md` | {{如：范围界定}} | 修改 | {{原句 → 新句}} |
| `specs/features/{{功能名}}/技术方案.md` | {{如：API 设计节}} | 新增 | {{设计点 + →AC-xxx 标注}} |
| `specs/features/{{功能名}}/任务规划.md` | {{如：变更日志节}} | 追加 | {{CR-xxx 摘要行}} |

> 任务规划正典不追加变更任务详情（详情留在归档的变更文件夹里可查），只追加一行变更记录，避免正典无限膨胀。

## 变更日志条目（追加到每份被修改文档末尾）

```markdown
---
## 变更日志 (Change Log)
### CR-{{编号}}: {{变更标题}} ({{YYYY-MM-DD}})
**类型**: {{微调/扩展/重构}}  **详情**: specs/changes/archive/{{功能名}}/{{日期}}-CR-{{编号}}-{{中文slug}}/
```

## 归档动作

1. 核验 变更任务.md 完成状态全勾、review 全 PASS
2. 执行上表归并
3. 变更文件夹移入 `specs/changes/archive/{{功能名}}/{{YYYYMMDD}}-CR-{{编号}}-{{中文slug}}/`（slug 沿用原目录名，不改写）
4. 开发日志.md 追加归档记录
