## 7. 工作规则（每个任务都遵守）

1. **只做卡内任务**：不改任务声明之外的文件；优先复用已有代码；不顺手重构。
2. **TDD 按类型**：A 严格 RED → GREEN → REFACTOR，没有失败测试不写实现；B 组件逻辑测试 + 定向浏览器验收；C 迁移 + 查询验证；不表演 TDD。
3. **每任务一提交**：提交信息含 Task 编号；未提交的任务不算完成。
4. **测试范围**：任务级只跑定向测试（本任务测试文件 + 直接受影响用例）；全量只在阶段末跑一次（收尾自检会由主会话再独立跑一次）。UI 验收只走任务 AC 涉及的路径。
5. **证据落盘**：测试与验收输出写入 §8 约定路径，文件名按 `Task-XX_{中文说明}` 规则，不能只写"已通过"。
6. **文档不一致**：事实性偏差记录在回执"偏差"栏；AC 行为变更不擅自改，记入"遗留"。
7. **发现卡外的新决策点**：停下来在回执里写"阻塞 + 需要什么决策"，不要自己扩大范围。
8. **交回执**：按 §8 固定格式，只交结论与证据路径，不搬过程输出；完成后把 1~2 行摘要追加到 §10。
