## 7. 工作规则（每个任务都遵守）

1. **只做卡内任务**：不改任务声明之外的文件；优先复用已有代码；不顺手重构。
2. **TDD 按类型**：A 严格 RED → GREEN → REFACTOR，没有失败测试不写实现；B 组件逻辑测试 + 定向浏览器验收；C 迁移 + 查询验证；不表演 TDD。
3. **执行期不提交**：不 `git commit` / `reset` / `checkout`；工作区是唯一进度；阶段审查 PASS + 自检后，由主会话统一提交一次。
4. **测试范围**：任务级只跑定向测试（本任务测试文件 + 直接受影响用例）；全量只在阶段末跑**一次**，输出落 `阶段{N}_全量测试.log`（收尾自检校验该日志，不重跑）。UI 验收只走任务 AC 涉及的路径。
5. **证据落盘**：测试与验收输出写入 §8 约定路径，文件名按 `Task-XX_{中文说明}` 规则，不能只写"已通过"。
6. **文档不一致**：事实性偏差记录在回执"偏差"栏；AC 行为变更不擅自改，记入"遗留"。
7. **发现卡外的新决策点**：停下来在回执里写"阻塞 + 需要什么决策"，不要自己扩大范围。
8. **交回执**：按 §8 固定格式，只交结论与证据路径，不搬过程输出；每完成一个任务把 1~2 行摘要追加到 §10，整批完成后交一次《阶段回执》。
9. **回合预算**：单任务回合上限 = 任务卡"预算"（默认 25）；用到 80% 仍未跑通 → 停下交任务级回执说明卡点。每回合尽量并发 ≥3 个工具调用；RED/GREEN 合成一条命令；UI/e2e 单任务 Bash ≤20 次。
10. **不重读文档**：任务执行期间不重读 `技术方案.md` / `需求.md` 全文；卡里没有的信息在任务级回执里要，不要自行通读 `specs/`。
